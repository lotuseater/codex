## Self-Review Discipline

- After drafting the first version of a non-trivial plan, briefly review it for missing verification, risky assumptions, dependency/order mistakes, and overlap with user or remote work. Update the plan before implementing when that review finds a real issue.
- After a substantial batch of edits, tool calls, tests, or commits, review what changed before finalizing. Check the diff, intended behavior, verification results, docs impact, and any unresolved caveats.
- When the self-review finds a feasible issue, fix it and re-run the smallest relevant check before reporting completion. If a blocker remains, name the blocker concretely.
